# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed
- (fork) The new `dexpa_sdk::scan` module (`read_input`, `report_for`) is the scan the CLI and the GUI share. A corrupt DEX file inside an APK keeps partial results: the manifest and the SDK evidence that does not need that DEX still show, and only the findings and class list say why they are unavailable. A file with DEX magic that does not parse reads "not a readable DEX file", an APK with no manifest says so, and the sample-app label applies only to the sample button.
- (fork) The README, the GUI README and the architecture notes describe the fork's GUI, and the README links the fork's site (https://j18bharati.github.io/dex-parser-analyzer/) next to the original's. The Pages deploy also runs on changes to `dex-sdk/`.
- (fork) Release wasm bundle (`nix build .#dex-gui`, the `.wasm` file): 2,501,054 bytes on `main`, built locally from the branch point, to 3,513,613 bytes with the fork's GUI (about 1.0 MB more: `dexpa-sdk`, the manifest and ZIP code, and the new views).
- (fork) The GUI has a new shell without Bootstrap: an arrival screen with drop and sample, `.apk` and `.dex` files, and a staged load that shows the SDK report before the findings and class list. The results are tabs: SDKs (with the evidence for each and a note on what a scan cannot prove), Manifest, Findings (rows reachable by keyboard, with labelled details) and Classes (with a case-insensitive filter). Every table shows at most 500 rows and says how many there are. A file that is neither an APK nor a DEX file is an error in the page, with no empty tabs. A file over 200 MiB or an unreadable archive is an error in the page, and the next file still loads.
- (fork) `dexpa-sdk` is `publish = false` and no longer in the release workflow's `CRATES`, so the fork publishes no crates; `dexpa-cli` depends on it, so a `dexpa-cli` release from the fork would fail (RELEASING.md).
- (fork) An APK's DEX files stop at the first missing number, as ART's loader does: with `classes.dex` and `classes3.dex` only `classes.dex` is app code. An archive with two entries of the same name (`classes.dex` or `AndroidManifest.xml`) is refused, because zip readers disagree on which one wins.
- (fork) A manifest string attribute is read the way Android reads it: one with a resource id (every `android:` attribute, which Android reads through `TypedArray`) by its typed value, one without (such as `package`, read through `XmlPullParser`) by its raw string, each falling back to the other. An APK whose two disagree no longer shows the decoy.
- (fork) `<uses-permission-sdk-m>` counts as a permission, as `<uses-permission-sdk-23>` does.
- (fork) An `<activity-alias>` name is no longer SDK evidence: Android never instantiates it, so an app can name one after any SDK.
- (fork) `dexpa sdks` refuses a DEX v041 container that holds more than one DEX file, since only the first would be read and the rest of the app's classes would go uncounted.
- (fork) `sdks diff` compares class evidence only when either report's manifest was not read, so manifest evidence that is merely unread is not shown as lost.
- (fork) `dexpa` errors are escaped like its other output, since they can quote a report's fields or an APK's text.
- (fork) `dexpa sdks` on an APK whose manifest does not parse prints a warning, reports the DEX evidence alone and exits 0, with the error in the new `manifest_error` field. It used to exit 1, so one bad manifest hid the whole report. An APK without `classes.dex` still exits 1.
- (fork) `dexpa sdks diff` refuses two reports made with different catalogues (it would have shown the difference as SDKs added and removed), and warns when a report has no fingerprint or the two packages differ.
- (fork) `dexpa sdks` text output escapes control characters, bidirectional marks and overrides, and invisible format characters (zero-width, Cf) from the APK, so a crafted package or class name cannot rewrite the terminal or pass for another name.
- (fork) `sdks diff` marks an SDK added or removed as `uncertain` when the other report's manifest was not read (DEX-only input or `manifest_error`), and says so on stderr. Before, a manifest that failed to parse turned every manifest-backed SDK into a `strong` removal.
- (fork) A `classesN.dex` entry that is not a DEX file is an error, as it is for ART. It used to be skipped silently, leaving the app's code undercounted.
- (fork) Exodus signatures are matched in one `RegexSet` pass over the class names instead of one pass per signature.
- (fork) The bundled `facebook` entry matches the SDK's own packages (`com.facebook.appevents`, `.login`, `.share`, `.ads`, `.gamingservices`, `.applinks`) and its meta-data keys, no longer all of `com.facebook`. The F-Droid evaluation found Fresco (React Native's image library) reported as the Facebook SDK.
- (fork) An APK's DEX files are now the archive-root `classes.dex`, `classes2.dex`, ... in numeric order, which is what Android loads. Before, entry names were sorted as text, so `classes10.dex` came before `classes2.dex`, and any `*.dex` anywhere in the archive (for example `assets/plugin.dex`) was read as app code. Each entry read is capped at `MAX_DEX_ENTRY_BYTES` (256 MiB), and their sum at `MAX_TOTAL_DEX_BYTES` (1 GiB), so many small deflated entries cannot inflate to many GiB; going over is an error, not a truncation. `read_dex_buffers_from_bytes_with_limit` and `..._with_limits` take a caller's limits.
- The GUI loads nothing from a third party: Bootstrap's CSS is self-hosted (the fork has since removed Bootstrap), the unused highlight.js (it ran before the app rendered, so it never highlighted anything) is gone, and a release build carries a Content-Security-Policy that allows only the page's own scripts, styles and wasm. The Pages deploy builds the bundle with the flake (pinned trunk, cached) and runs on changes to any crate the GUI links, not only `dex-gui/`.
- **Breaking:** `Finding` gains `cwe` (the rule's CWE number) and `remediation` (what to change), filled by the engine from the new `rules::RULES` catalogue; both deserialize as `null` when absent, so older JSON reports still load.
- The report lists findings most severe first, with exact duplicates removed, before `max_findings` truncates it, so a cap keeps the most severe findings (previously it kept the first ones emitted). `Severity` is now `Ord`.
- **Breaking:** the crates are renamed `dexpa-core`, `dexpa-analysis` and `dexpa-cli` (import them as `dexpa_core` and `dexpa_analysis`; `dex-cli` is taken on crates.io), and the CLI binary is `dexpa`. The directories keep their names.
- **Breaking:** `DexFile::strings()` yields `DexResult<&str>` instead of `&str`, so a malformed entry is reported instead of panicking.
- The project is dual-licensed MIT OR Apache-2.0 (previously MIT under the FossRust name). Every published crate ships both licence files, and NOTICE attributes the Androguard-derived test fixtures.
- Every crate uses edition 2024 and the shared `[workspace.package]` metadata (description, repository, keywords, categories). `rust-version` is 1.99, and `rust-toolchain.toml` pins Rust 1.99.1.
- The README demo link, the GUI title and the GUI header link point at github.com/dhilipsiva (the fossrust.github.io URL returned 404).
- The GUI moves to Leptos 0.8. Its release bundle shrinks from about 6 MB to 2.4 MB of WebAssembly.
- Dependencies: zip 9 (fixes RUSTSEC-2026-0367, -0368 and -0369), anyhow 1.0.104 (RUSTSEC-2026-0190), bytes 1.12.1 (RUSTSEC-2026-0007), petgraph 0.8 and thiserror 2. The unused nom dependency is removed.
- The fixture-sweep tests fail when a fixture is not a DEX file, instead of skipping it.

### Added
- (fork) **Breaking for struct literals:** `SdkReport` gains `unreadable_classes` (class definitions whose descriptor is not a class, left out of `class_count`), `catalogue_fingerprint` (FNV-1a 64 over the catalogue's ids, rules and meta-data keys, from the new `Catalogue::fingerprint`) and `manifest_error`. Both deserialize as `null` when absent, so earlier reports still load; `schema_version` stays 1.
- (fork) `fdroid.py run` records a failed download (404, timeout, hash mismatch) as that APK's failure and continues, times out a hung tool after `--tool-timeout` seconds (default 600), keeps a report only when both its analyses succeeded, and starts by clearing `eval/reports/`, so no report from an earlier run (another lock, an APK that now fails, or one an aborted run never reached) survives. A tool that cannot start or prints something other than JSON, or a broken HTTP response (`IncompleteRead`, `BadStatusLine`), is that APK's (or that diff's) failure, not the end of the run. `select` writes the lockfile as UTF-8, so a version name outside the Basic Multilingual Plane no longer makes it unreadable.
- (fork) An F-Droid evaluation of `dexpa sdks` (`eval/`, `nix develop .#eval`). `just fdroid-select` verifies F-Droid's signed `entry.jar` against the published key, checks `index-v2.json` against the sha256 that `entry.json` pins, and writes a lockfile of 10 apps × 3 versions per stratum (`Tracking`, `NonFreeNet`, no anti-feature). `just fdroid-eval` downloads exactly those APKs, one at a time, against their pinned sha256 and size, within per-file, total, time and free-disk budgets. It analyses each APK, deletes it, and writes `eval/results.json` and `eval/TABLE.md`. `just eval-test` runs offline. A `manifest_json` example prints a parsed manifest. Results over 90 APKs are in `eval/README.md`: the manifest parser agrees with the index on every field except values the index adds itself.
- (fork) `dexpa sdks <FILE>` lists the SDKs in a DEX file or APK with their evidence (`--catalogue` to replace the bundled list, `--exodus` to add an Exodus tracker file, `--format text|json`), and `dexpa sdks diff OLD.json NEW.json` compares two saved reports. `dexpa <FILE>` and its output are unchanged. `dexpa-sdk` is now published with the other crates, since `dexpa-cli` depends on it; `report::build_report` builds a report from DEX buffers and a manifest. Known-positive DEX fixtures are compiled from Java sources by `just sdk-fixtures`.
- (fork) `dexpa-sdk` reports and diffs: `report::SdkReport` (its own `schema_version: 1`, with the ODbL attribution when Exodus data was used) and `diff`, which compares two reports and emits `sdk_added`, `sdk_removed` (each `strong` when backed by manifest evidence, `uncertain` when backed by class names alone, which R8 can rename) and `sdk_evidence_changed`. Counts and DEX placement are not compared.
- (fork) `dexpa-sdk` matches SDKs. `catalogue` loads this project's hand-written TOML list (25 SDKs, compiled in) and imports Exodus tracker files supplied at run time; Exodus data is ODbL and never committed. `matcher` reports each SDK with its evidence: defined classes under a package prefix, manifest components (names R8 keeps, so this evidence survives minification), and exact meta-data keys. Prefixes match on package boundaries; Exodus signatures are anchored at the start of the class name, and invalid ones are skipped and counted.
- (fork) A new crate `dexpa-sdk` (`dex-sdk/`). `inventory` lists the classes an app *defines* (from each DEX file's `class_defs`, so types it only references are not counted), with methods per class, per-DEX totals, and class and method counts per package prefix at depths 2 to 4.
- (fork) `dexpa_core::axml` parses Android binary XML, and `dexpa_core::manifest` reads `AndroidManifest.xml` from bytes or an APK: package, versionCode and versionName (typed, with references kept unresolved), min and target SDK, permissions, activities, aliases, services, receivers and providers (name, exported, authorities), and meta-data with its owning component. `android:` attributes resolve by framework resource id, so names stripped by resource shrinking still resolve. Input is bounded (`MAX_DEPTH`, `MAX_DECODED_STRING_BYTES`, `MAX_MANIFEST_BYTES`) and malformed input is an error, never a panic. A `parse_manifest` fuzz target joins the weekly campaign.
- Browser smoke tests for the GUI (wasm-bindgen-test in headless Chromium, `nix develop .#wasm-test -c just test-wasm`, and the CI job `gui-smoke`): the app mounts, and the analyzer runs in wasm32 and its findings render.
- A release workflow (`.github/workflows/release.yml`, runbook in RELEASING.md): a `v*` tag publishes `dexpa-core`, `dexpa-analysis` and `dexpa-cli` to crates.io, attaches `dexpa` binaries for Linux (x86_64, aarch64), macOS (aarch64) and Windows (x86_64) with SHA256SUMS and build provenance to the GitHub Release, and redeploys the GUI. A manual run is a rehearsal that creates nothing. `just release` rehearses locally.
- Flake packages: `nix build .#dex-cli` (also the default, so `nix run . -- app.apk` works) and `nix build .#dex-gui`, the static GUI bundle.
- A positive and a negative test for every rule id, against DEX fixtures compiled from documented Java sources in `dex-analysis/tests/fixtures-src` (`nix develop .#fixtures -c just fixtures`, with a pinned R8), and a test that docs/rules.md, the catalogue and the tests list the same ids, CWEs and remediation text.
- `dexpa` reads APKs and multi-dex zips as well as `.dex` files, prints `--format json` (a versioned schema, documented in dex-cli/README.md), and exits with 2 when a finding meets `--fail-on <severity>` (1 on unreadable or unparsable input). Integration tests drive the binary.
- `deny.toml`, with `cargo deny` in CI, and Dependabot updates for Cargo and GitHub Actions.
- A rebuilt CI workflow: fmt, clippy (native and wasm32), tests, docs, cargo deny, MSRV and workflow lint, with SHA-pinned actions.
- `just ci` as the local gate.
- cargo-fuzz targets for the parser, bytecode decoding and the analyzer (`fuzz/`, `just fuzz`), with a pinned-nightly dev shell and a weekly fuzz workflow.
- docs/architecture.md and docs/rules.md, per-crate READMEs, CONTRIBUTING.md and SECURITY.md.

### Removed
- The committed GUI build (`dex-gui/dist`) and two fixtures that were 14-byte "404: Not Found" pages rather than DEX files.

### Fixed
- (fork) An Exodus signature that does not compile on its own (for example an unbalanced `a)|(b`) is now skipped. Before, it was wrapped as `^(?:a)|(b)`, which compiles, and its second branch was not anchored.
- (fork) `read_dex_buffers_from_bytes_with_limits` and `read_manifest_from_apk_bytes_with_limit` accept `u64::MAX` as "no limit". `limit + 1` overflowed: a panic in debug builds and, in release, every entry read as empty.
- `M1_HARDCODED_SECRET` no longer reports ordinary text on entropy alone: the entropy trigger only considers token-shaped literals (20+ base64, base64url or hex characters with letters and digits, not made of words, not an algorithm name), so SQL, URLs, messages, identifiers, file names and transformation strings no longer match. On the bundled sample `Annotation_classes.dex` the secret findings drop from 587 to 1 (the remaining one is a `password=` pattern), and on `classes.dex` from 145 to 0; none of the dropped literals was a token.
- `SNK_URL_CONSTRUCTOR` and `SNK_WEBVIEW_LOAD_URL` never fired: they checked the receiver register instead of the URL argument.
- `M10_CIPHER` and `M10_DIGEST` compare whole algorithm tokens instead of substrings, so a string such as `"description"` no longer marks a call as DES and `RSA/ECB/...` is not reported as ECB. Calls using a recognised strong algorithm (AES in a mode other than ECB, ChaCha20, RSA, SHA-2, SHA-3) are no longer reported at Low. A bare `"AES"`, which means ECB on Android, is reported High.
- `M7_WEBVIEW_JS_INTERFACE` and `M7_WEBVIEW_FILE_ACCESS` no longer count `setJavaScriptEnabled(false)` or `setAllowFileAccess(false)` as enabling.
- Three crashes on crafted input are now errors. An out-of-range `class_data_off` and an out-of-range `string_data_off` are rejected by `parse_dex` with `SectionOutOfBounds`. A literal whose 64-byte preview cut fell inside a multibyte character no longer panics the analyzer (thanks to @bilieebiliee1-design, whose PR #1 found it).
- Crafted counts and nesting no longer exhaust memory or the stack: declared counts cap their allocations at the input length, encoded values nest at most 64 deep, a sleb128 is at most five bytes, and `data_off + data_size` saturates.
- Every leb128 read in the parser starts at a bounds-checked offset, and a `method_idx` in class data that points past `method_ids` is an `InvalidIndex` error instead of a panic.
- The GUI page no longer requests a nonexistent `dex-gui.js`.
